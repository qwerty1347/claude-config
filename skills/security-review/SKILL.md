# ISMS 보안성 검토 (정보보호 요구사항 49개 항목)

검토만 한다. **대상 repo 코드는 고치지 않는다.** 결과물은 전부 바탕화면 결과 폴더에 만든다.

## 0. 입력 정리

- 대상: 인자로 받은 경로, 없으면 현재 작업 디렉터리. 프로젝트명 = repo 폴더명.
- 사용자가 준 **가정**(예: "더미가 아닌 실제 API 데이터", "VITE_USE_DUMMY=false")은 보고서 머리말에 그대로 적고, 그 가정대로 빌드·검증한다.
- 결과 폴더: `[Environment]::GetFolderPath('Desktop')` 아래 `<프로젝트명>_보안성검토결과\` (사용자가 다른 이름을 주면 그 이름, 명백한 오타는 고치고 알린다).
- 참고 사례(있으면 양식 확인용으로만 읽음): `D:\문서\ai-wish\보안성검토\` — `보안성_검토_보고서.md`(Designer), 결재 HTML 보고서, 체크리스트 docx, 코드 스크린샷 폴더.

## 1. 조사

1. repo 구조와 CLAUDE.md(상위 `ai-wish\CLAUDE.md` 포함)를 읽는다. FE 전용인지, 백엔드·DB·업로드·외부 API·감사로그가 있는지 파악한다.
2. 소스 전체를 읽는다(작은 repo면 직접, 크면 영역별로). 아래 "항목별 확인 포인트"를 기준으로 근거 파일·줄 번호를 모은다.
3. 의존성: `npm audit` / `npm audit --omit=dev`(운영 번들 영향 구분), Python 은 `pip-packages/` 버전 확인.
4. 공통 인프라(인증 위임·사이드바·게이트웨이)는 `wish-landing-page`(`auth-guard.js`, `sidebar.js`), `wish_login`, `local-dev\landing\nginx.conf`에서 확인한다. 운영 서버 확인은 `"C:\Program Files\Git\usr\bin\ssh.exe" wish '<읽기 전용 명령>'`만 쓰고, 안 되면 "미확인"으로 적는다.
5. **재현 검증은 임시 폴더(scratchpad)에서만** 한다. 예: 가정대로 `--outDir <scratch>` 빌드 후 번들 검색. 시크릿은 **가짜 값으로 대체**해서 빌드하고, 실제 `.env` 값은 화면·문서에 출력하지 않는다(필요하면 `grep -cF` 로 포함 여부 개수만).
6. 실제 운영 API·외부 시스템을 호출하지 않는다. 볼 수 없는 쪽(외부 서버의 CORS·호출 제한·재검증)은 "확인하지 못한 것"에 적는다.

## 2. 판정 규칙

- 값: `Y`, `Y(부분)`, `Y(공통)`, `N`, `N/A`. N·N/A 는 사유 한 줄 필수.
- 회원가입·비밀번호·계정·세션 항목은 auth_service 위임이면 `N/A`(사유 "랜딩페이지에서 처리" / "로그인에서 관리").
- 문제는 등급을 붙인다: 🔴 상(배포 차단) / 🟠 중 / 🟡 하. 하나의 원인이 여러 항목을 N 으로 만들면 발견 사항 1건(F-n)으로 묶고 관련 항목 번호를 나열한다.
- 확인 못 한 것을 Y 로 쓰지 않는다.

## 3. 스크린샷

문제(N)와 핵심 Y 근거마다 코드 발췌 스크린샷을 만든다. 파일명은 체크리스트 docx 항목 제목인 `<항목번호> <항목명>-<순번>` (예: `2-6 타 이용자 권한 도용 방지-1`, `2-13 XSS 방지-2`) — 항목명은 `scripts/shots.py` `TITLES`, 순번은 항목별 자동이라 spec 에는 `item`(번호)만 적는다. 무엇을 보여 주는지는 `caption`에 쓰고, 문제 줄은 강조.

1. scratchpad 에 `spec.json` 작성 (형식은 `scripts/shots.py` 머리 주석). 빌드 산출물·명령 출력(npm audit 등)은 텍스트 파일로 저장해서 같은 방식으로 찍는다(긴 한 줄은 `fold -w 110`).
2. 실행: `PYTHONIOENCODING=utf-8 python ~/.claude/skills/security-review/scripts/shots.py <spec.json> "<결과폴더>/스크린샷"`
3. 2~3장은 Read 로 열어 잘림·강조 위치를 확인한다.

## 4. 체크리스트 docx

1. scratchpad 에 `rows.json` 작성 — 49개 `[반영여부, 사유]`, 위 표 순서. 사유는 한 줄.
2. 실행: `PYTHONIOENCODING=utf-8 python ~/.claude/skills/security-review/scripts/checklist.py <rows.json> "<서비스 표시명>" "<결과폴더>/정보보호_요구사항_체크리스트_<서비스명>.docx"` (python-docx 없으면 스킬 폴더 `pylib/`에 자동 설치)
3. docx 를 다시 읽어 제목·N 행 몇 개를 확인한다.

## 5. 보고서 `보안성_검토_보고서.md`

아래 순서로 쓴다. 보고서 표의 판정과 docx 판정이 같아야 한다.

1. 제목·머리말: 검토일(KST), 대상(repo·브랜치·예정 URL), 단계, 기준, **검토 가정**
2. 결론 요약: Y/N/N/A 집계표(관리적·기술적·총합), **배포 판정**(가능 / 보류 + 차단 이슈), 등급별 발견 사항 표
3. 서비스 특성: 구성, 인증, 외부 연동, 취급 데이터, 업무 영향
4. 검증 방법 표(확인·방법·결과) + **확인하지 못한 것**
5. 주요 발견 사항 F-1…: 등급·관련 항목 / 내용 / 영향 / 근거 스크린샷 파일명(`<항목번호> <항목명>-<순번>`) / 조치 권고 (WISH 표준: auth_service 위임 인증, CSRF Origin 검증, slowapi, audit_logs, Vault 시크릿 — 평문 시크릿·포트 임의 배정 권고 금지)
6. 체크리스트 외 기타 권고(보안 헤더, CORS 등)
7. 1. 관리적 / 2. 기술적 보호조치 표 (번호·상세항목·반영·근거)
8. 조치 우선순위 표(조치 → 해소 항목)
9. 첨부 목록

## 6. 마무리 보고
