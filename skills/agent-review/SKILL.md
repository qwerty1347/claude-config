# 병렬 리뷰 (MR 전 점검)

## 1. 변경 범위 확인
- `git diff HEAD --name-only`와 `git status --short`로 변경 파일을 모은다. 인자로 경로가 오면 그 경로만 본다.
- 변경이 없으면 알리고 멈춘다.
- 화면 변경 여부를 판단한다. `.tsx`·`.jsx`·`.vue`·`.css`·`.scss`·`.html`·`.blade.php` 등 화면 파일이 바뀌었으면 화면 변경으로 본다.
- 브라우저 도구(Playwright/Chrome MCP)가 없는 프로젝트라면 ui-ux-tester는 건너뛰고, 건너뛴 사실을 보고에 적는다.

## 2. 사전 체크 (에이전트 실행 전)
- `package.json`에 있는 스크립트만 실행한다: lint, `npx tsc --noEmit`(tsconfig가 있을 때), build.
- 실패하면 에러를 보고하고, 에이전트 실행을 계속할지 사용자에게 묻는다.

## 3. 에이전트 병렬 실행 (백그라운드)
각 에이전트에게 변경 파일 목록을 주고, 아래 공통 지시를 붙인다.

> 파일을 수정·생성하지 말고 지적만 하라. 각 항목에 `파일:라인`, 심각도(높음/중간/낮음), 이유, 수정 제안을 적어라.

| 에이전트 | 맡는 일 | 실행 조건 |
|---|---|---|
| code-reviewer | 버그, 로직 오류, 코드 품질 | 항상 |
| security-auditor | 보안 취약점(인증, 입력 검증, 비밀값 노출, XSS 등) | 항상 |
| ui-ux-tester | 브라우저로 변경된 화면을 열어 실제 동작 확인 | 화면 변경이 있을 때만 |

실행 순서:
1. code-reviewer와 security-auditor를 **한 메시지에서 동시에, 백그라운드로(run_in_background)** 호출한다.
2. 화면 변경이 있으면 이어서 개발 서버 주소를 정한다.
   - 인자로 주소를 받았으면 그 주소를 쓴다.
   - 없으면 사용자에게 묻는다: "개발 서버 주소를 알려주세요. 서버가 꺼져 있으면 켠 뒤 주소를 알려주거나, '건너뛰기'라고 답해주세요."
3. 주소를 받으면 ui-ux-tester를 백그라운드로 호출한다. '건너뛰기'면 호출하지 않는다. 서버는 직접 띄우지 않는다.
4. 호출이 끝나면 기다리지 말고 "리뷰를 백그라운드에서 실행 중입니다"라고 알리고 턴을 끝낸다.

ui-ux-tester 추가 지시:
- 변경된 화면의 주요 동작(클릭, 필터, 차트 표시, 반응형)을 확인하고 결함만 보고한다.

## 4. 결과 종합
- 실행한 모든 에이전트의 완료 알림이 오면 그때 결과를 합친다. 일부만 끝났으면 기다린다.
- 중복 항목은 합친다.
- **반드시 수정 / 권장 / 무시 가능** 세 그룹으로 나누고, 그룹 안에서는 심각도순으로 정렬한다.
- 각 항목에 어느 에이전트가 찾았는지 표시한다.
- 맨 위에 한 줄 결론을 쓴다: MR 가능, 또는 수정 후 MR.

## 5. 수정
- 보고만 하고 멈춘다. 사용자가 승인한 항목만 수정한다.
